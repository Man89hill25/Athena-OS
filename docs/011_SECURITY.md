# 011_SECURITY.md - المعايير وسياسات الأمان

## 1. Purpose (الهدف)
تحديد الضوابط الأمنية الشاملة لحماية بيانات الباحثين والمصادر النادرة والتأكد من أمان عمليات التواصل واستخدام المفاتيح البرمجية.

## 2. Responsibilities (المسؤوليات)
* التشفير التام للبيانات أثناء التخزين (Data at Rest) وأثناء النقل (Data in Transit).
* حماية مفاتيح API الخاصة بـ Google Gemini وعدم كشفها في العميل إطلاقاً.
* حماية قاعدة البيانات من هجمات الحقن (SQL Injection / Prompt Injection).

## 3. Dependencies (الاعتماديات)
* يرتبط بـ `006_DATABASE_ARCHITECTURE.md` و `007_AI_ARCHITECTURE.md`.

## 4. Internal Structure (الهيكل الداخلي)
* **Secret Manager**: المحرك الخفي لتعامل مع البيئة والمتغيرات الحساسة.
* **Input Sanitizer**: الفاحص والمطهر لجميع استعلامات المستخدم ضد هجمات Prompt Injection.
* **Database Vault**: خيار تشفير قاعدة SQLite عبر SQLCipher في البيئات الحساسة.

## 5. Future Expansion (التوسع المستقبلي)
* دمج المصادقة البيومترية والمفاتيح الصلبة (Hardware Keys / FIDO2) لحماية المكتبات الخاصة.

## 6. Risks (المخاطر)
* تسريب مفاتيح API في حالة مشاركة المشروع أو رفع أكواد التطوير بدون حذر.

## 7. Engineering Notes (الملاحظات الهندسية)
* يمنع منعاً باتاً تخزين أي مفتاح API كقيمة نصية صريحة (Hardcoded Secret) في أي كود مصدر.
