# 033_API_DESIGN.md - تصميم واجهات برمجة التطبيقات (API RESTful & IPC)

## 1. Purpose (الهدف)
توثيق كافة مسارات واجهات برمجة التطبيقات (API Routes) لخادم Express المحلي لضمان وضوح الاتصال بين واجهة المستخدم والخدمات الخلفية.

## 2. Responsibilities (المسؤوليات)
* توفير مسارات RESTful للعمليات على الكتب، البحث، الرسوم البيانية، والاستدلال الذكي.
* توحيد نمط الاستجابات (Standard JSON Response):
  ```json
  {
    "success": true,
    "data": {},
    "error": null,
    "timestamp": "2026-07-23T14:27:00Z"
  }
  ```
* معالجة الاستجابات التدفقية (Streaming SSE Responses) لطلبات توليد النصوص والوكلاء.

## 3. Dependencies (الاعتماديات)
* يوجه الشفرات في `server.ts` و `036_BACKEND_DESIGN.md`.

## 4. Internal Structure (الهيكل الداخلي)
* **API Endpoints**:
  * `GET /api/health`: الفحص التشغيلي المباشر للخادم.
  * `GET /api/docs`: جلب وتحليل قائمة وثائق النظام المعمارية (000-049).
  * `POST /api/search`: البحث الهجين واسترجاع المطابقات مع التصفية.
  * `POST /api/ai/chat`: إرسال الطلبات إلى Gemini 2.5 مع دعم البث الحكائي.
  * `POST /api/library/upload`: رفع واستيراد الكشوفات المستندية.

## 5. Future Expansion (التوسع المستقبلي)
* إضافة واجهات GraphQL للاستعلامات المخصصة على قواعد البيانات المعقدة والشبكية.

## 6. Risks (المخاطر)
* إغفال التحقق من المدخلات قد يسبب أعطال غير متوقعة داخل خادم Express.

## 7. Engineering Notes (الملاحظات الهندسية)
* يجب أن تتم إدارة كل مسار بداخل مغلف الاستثناءات `try/catch` لإرجاع كود الحالة المناسب (400, 404, 500).
