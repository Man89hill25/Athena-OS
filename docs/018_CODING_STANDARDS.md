# 018_CODING_STANDARDS.md - معايير وضوابط كتابة الكود

## 1. Purpose (الهدف)
توثيق المعايير البرمجية الصارمة لضمان كتابة كود برمجي نظيف، متسق، ومقروء بين جميع أجزاء المشروع، وفق متطلبات التوجيهات الهندسية.

## 2. Responsibilities (المسؤوليات)
* الامتثال التام لـ TypeScript Strict Mode والوقاية من استخدام `any` غير المبرر.
* كتابة جميع التعليقات التوضيحية للشفرة والتوثيق باللغة العربية حصراً.
* المحافظة على استخدام الأسماء الإنجليزية للمتغيرات والدوال والملفات والمجلدات.

## 3. Dependencies (الاعتماديات)
* يفرض معاييره على جميع ملفات الكود تحت `/src` و `/server`.

## 4. Internal Structure (الهيكل الداخلي)
* **Naming Conventions**: `camelCase` للمتغيرات والدوال، `PascalCase` للمكونات والأنواع، `SNAKE_CASE` للثوابت.
* **Component Modularity**: عدم تجاوز أي ملف 300-400 سطر مع تجزئة المكونات الكبيرة إلى ملفات فرعية.
* **Imports Order**: استيرادات المكتبات أولاً، ثم المكونات، ثم الأنواع والخدمات المساعدة.

## 5. Future Expansion (التوسع المستقبلي)
* تطبيق أدوات التحليل الساكن المخصصة (Custom ESLint Rules) لمنع استخدام الأنماط الممنوعة تلقائياً.

## 6. Risks (المخاطر)
* تراجع انضباط الشفرة البرمجية مع زيادة عدد الملفات والتطوير السريع.

## 7. Engineering Notes (الملاحظات الهندسية)
* يجب أن تجتاز جميع التعديلات فحص `lint_applet` و `compile_applet` بنجاح قبل الاعتماد المالي أو البرمجي.
